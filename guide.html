QA ASSISTANT ／ 使い方

QA アシスタントの作り方

製品の ZIP と、この一式を Claude に渡すと、QA Assistants / QA ZERO の「AIアシスタント」画面で動くアシスタントを1本作ってくれます。人が読むのはこのページだけで足りるように作ってあります。
渡すもの 製品 ZIP ＋ この一式 使う人 どなたでも（コードの知識は不要）

もくじ

01

これは何か

アシスタントは、4つのファイル（動作定義・翻訳2つ・プラグインの入り口）＋アイコンでできています。これを手で書くのは大変なので、Claude に書かせるための道具立てがこの一式です。

渡すもの（2つだけ）

  • 製品の配布 ZIP を展開したフォルダ（qa-heatmap-analytics/ か qa-zero/） 製品としてお使いのものと同じ、ふつうのプラグイン ZIP です。この中に、アシスタントの仕組み・取れるデータの一覧・検証プログラムが全部入っています。特別な準備は要りません。
  • この一式（指示書 CLAUDE.md・検証ラッパー validate.php・見本 examples/） 人が維持するのは、この指示書1枚とこのページだけです。
  • Claude は見本をまねて書き、検証プログラムで自己採点し、合格（VALID）になるまで直してから完成を報告します。
  • できたフォルダを WordPress のプラグイン置き場に入れて有効化すると、「AIアシスタント」画面に現れます。
02

正本マップ — 何が「真実」か

設計の芯は「製品のコードが正本。写しは一つも作らない」です。人が書いた説明書は、製品が変わると静かに古くなり、しかも量が多すぎて人の目では照合できません。だから説明書を持たないという選択をしています。

Claude は製品 ZIP の中の実物（スキーマ・データの一覧・動作コード）を直接読む。写しが無いので、古くなりようがない。人が維持するのは右の2ページだけ。
  • 製品のコードが常に正しい。 指示書の記述とコードが食い違ったら、コードが正しい。Claude には「勝手に説明に合わせず、食い違いを報告しろ」と指示してあります。
  • ZIP を新しくすれば、それだけで最新になります。 キットを作り直す・写しを更新する、といった作業はありません。
  • 使った ZIP がどのバージョンかは、ZIP の中の qahm.php の Version 行と qahm-const.php に書いてあります。
03

Claude への渡し方

  • この一式のフォルダを開いて Claude Code を起動する（指示書が自動で読み込まれます）。
  • 展開した製品 ZIP の場所を伝える（同じフォルダに置いておけば、それだけで伝わります）。
  • あとはふつうの日本語で頼むだけ。技術用語は不要です。

頼み方の例

よく見られているページを上位10件、表で見せるアシスタントを作って。
期間は先月にして。
サイトに来た人にアンケートを取りたい。
質問は3つ（満足度・理由・自由記入）。答えは保存して、あとで一覧できるように。
  • Claude は構成を一度だけ確認してきます（会話の流れの案）。OK を出すと生成に入ります。
  • 完成時、Claude は検証に合格したこと（VALID）を示します。示されない場合は「検証は通った？」と聞いてください。
04

「VALID」の意味 — 合格＝正しい、ではありません

ここは知っておいてください。検証プログラムが見ているのは「壊れていないか」であって、「数字が正しいか」ではありません。

  • 検証されること：書き方の間違い（存在しない項目名・必須項目の書き忘れ・型の誤り）、つながりの間違い（存在しない画面へ飛ぶ指定・使っていない変数・翻訳の書き漏れ・計算式の文法）、同梱ファイルの形（余計なファイル・PHP の形・アイコンの形式）。 ここは機械が確実に止めます（検証エンジンは製品本体のもの＝管理画面で読み込むときと同じ判定です）。古い製品 ZIP を渡すと「古い世代」と表示され、このうち「つながり」と「同梱ファイル」は見られません。
  • 検証されないこと：数字が正しいか。 たとえば「セッション内で何番目に見られたページか」という順番の番号を合計して「PV」として表示しても、検証は VALID と言います（実際に見本がこの誤りを持っていて、実データで PV 333 のところを 1,252 と表示していました。2026-07 に修正済み）。
  • これも検証されません：結果が空っぽにならないか。 2つのデータを「名前」（流入元の名前など）で突き合わせる書き方をすると、仕組みの都合で1件も一致せず、空の表や 0 ばかりの数字が出ることがあります（それでも VALID です）。絞り込みの条件の書き方によっては、絞り込みが効かないまま全件が表示されることもあります。「データが無い」ように見えて、実は書き方の問題——ということがあります（→ 下の「動かないときの3チェック」②）。

だから、完成したら必ず「実データで数字を見てください」。 見慣れた画面（QA の管理画面）の数字と桁が合っているか、それだけでも十分な検査になります。おかしければ Claude に「この数字が管理画面と合わない。材料の選び方を実コードで確認して」と伝えてください。比べるときは、管理画面の期間をアシスタントと同じに合わせてから——管理画面の初期表示は直近1週間、アシスタントの初期値は直近30日ということがよくあり、そのまま並べると桁が合わないように見えます。

もうひとつ、期間を広げたら、数字が減らないことを確かめてください。 広い期間のほうが小さい——そうなったら、その数字は使えません。そこで止めて相談してください。桁が妥当に見えても、この検査だけが捕まえる壊れ方があります。とくに今日を含む期間（「今週」「今月」）で確かめてください（「過去7日」「過去30日」は昨日までを見るため、この壊れ方が出にくい組み合わせです）。※ 今日を含む期間を選んでも、今日の分はまだ集計に入っていません（昨日までの数字になります）＝これは不具合ではありません。

※ この「数字の正しさを機械で止める」仕組みは、2026-07-15 に一段目が入りました（材料の定義に「この列は順番の番号」といった意味づけ〔semantics 宣言〕が入っています）。この一式の検証ラッパーは、まだこの検査を呼び出しません。

05

動かないときの3チェック

  • ① 画面に出てこない／エラーになる → プラグインのフォルダ名と中の名前がずれている可能性。Claude に「フォルダ名と id が一致しているか、検証を通して確認して」と伝えてください。古いバージョンの製品に、新しい機能を使ったアシスタントを入れた場合もエラーになります（この場合は本体の更新が必要）。
  • ② 数字が全部ゼロ／表が空 → その期間・そのサイトにデータが無いか、集計の指定が噛み合っていない可能性。Claude に「期間を変えて試して。それでも0なら集計の指定を実コードで確認して」と伝えてください。それでも空のままなら「データ同士の突き合わせ（join）のキーが数字の ID になっているか、絞り込みの条件が実際に効いているか、実コードで確認して」と伝えてください（名前で突き合わせると1件も一致しない仕組み上の落とし穴があります）。
  • ③ 文字が「t:xxx」のように出る → 翻訳の書き漏れです。Claude に「日本語と英語、両方の翻訳が揃っているか確認して」と伝えてください。

どれも「Claude に何と言えばいいか」の形にしてあります。原因の特定は Claude 側が実コードを読んで行います。

検証プログラムが「検証エンジンが壊れています」と言ったときは、製品 ZIP を展開し直してください。（ZIP が壊れていると、検証が「合格」と誤って言ってしまうことがあるため、その状態を検知して止めるようにしています。）

※ アシスタントの「設定を保存する」機能は、サイトを1つ選んでいるときだけ働きます（画面上部で「全サイト表示」を選んでいると保存・読み込みが拒否される仕様です）。設定が保存できないときは、まずサイトの選択を確認してください。
